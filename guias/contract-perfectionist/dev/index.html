</Contratos listos para firma

Redacta el contrato final de un proyecto a partir de tres insumos, sin ambigüedad para ninguna de las partes.

  • Nunca inventa: partes, NIT, representante, alcance, valores y plazos salen literalmente de recursos/; si falta, [PENDIENTE: ...].
  • El Contrato Madre es inspiración estructural, no texto a copiar a ciegas.
  • El .docx se monta siempre sobre la plantilla corporativa y pasa un gate antes de entregarse.

</Arquitectura de cláusulas

Se ajustan a alcances y cotización

  • Consideraciones y objeto
  • Alcance funcional y cronograma
  • Valor y forma de pago
  • Mantenimiento y soporte
  • Garantías
  • Obligaciones y aceptación de entregables

Protección estándar: se mantiene

  • Propiedad intelectual
  • Reserva de información y terceros
  • Fuerza mayor
  • Suspensión y terminación
  • Cláusula penal
  • Vigencia y ley aplicable
<= ExcepciónLas cláusulas de protección solo cambian si el usuario lo indica para ese proyecto =>

</Script de montaje y gate

Construir
python scripts/build_contract.py build --data contratos/<cliente>/datos.json --out "contratos/<cliente>/Contrato - <Cliente> - <YYYY-MM-DD>.docx"

Monta sobre la plantilla corporativa y corre los mismos gates que check.

Verificar
python scripts/build_contract.py check --file "contratos/<cliente>/Contrato - <Cliente> - <YYYY-MM-DD>.docx"

Falla (código ≠ 0) si queda un [PENDIENTE ...] o se perdió el membrete o la línea de firma.

Opciones
--skip-check · pip install python-docx

--skip-check solo para borradores incompletos, nunca para entrega. El script monta; las cláusulas las redacta el agente.

</Ocho reglas no negociables

01

Nunca inventar información

Todo dato específico viene de recursos/; si no, placeholder explícito.

02

Consultar ante ambigüedad

No se asume la interpretación más probable.

03

Madre = estructura

El contenido de cada cláusula sigue a alcances y cotización.

04

Discreción y claridad

Sin lenguaje comercial ni mezclar clientes: qué, cuándo, cuánto y qué si falla.

05

Diseño corporativo obligatorio

Sobre Contrato - Plantilla Base.docx, nunca en blanco.

06

Líneas de firma físicas

Línea sobre cada nombre, con espacio para firmar.

07

Gate de entrega

Sin check aprobado no hay versión de entrega.

08

Datos sensibles en el repo

Preguntar antes de compartir o subir a un remoto.

</Síntomas frecuentes y qué hacer

?El gate falla por un [PENDIENTE ...]

Resolver el dato con el usuario o la fuente y regenerar; no se entrega con placeholders.

?El .docx perdió el membrete

Se montó fuera de la plantilla: volver a construir con build, no editar el documento a mano.

?Una cláusula admite dos lecturas

Detenerse y preguntar al usuario antes de redactar esa parte.

?Reemplazaron el Contrato Madre

Registrar el cambio en glosario-clausulas.md, sección Historial de versiones.
